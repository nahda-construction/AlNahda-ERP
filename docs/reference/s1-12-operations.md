# S1-12 — تشغيل Staging والتحقق من النشر

مرجع العمل [بطاقة S1-12](s1-12-lan-staging-draft.md) و[نطاق التنفيذ والاختبارات](s1-12-execution-plan.md). النطاق يخص تطبيق الاختبار الداخلي على Linux. القبول الميداني معلّق حتى جاهزية S1-13.

## تجهيز مثيل المكتب

1. سجّل SHA المصدر وإصداري Docker وCompose وإصدار حزمة Nginx. احفظ بصمتي صورة التطبيق وPostgreSQL 18 ومرجع ملفي Compose وقالب الوسيط في بيان إصدار خال من الأسرار. حمّل الصور بالبصمة قبل بدء الاختبار. يُسجل معرّف بناء الصورة المحلية منفصلًا إذا لم توجد لها بصمة نشر في سجل حاويات. لا تُعامل علامة صورة متغيرة كدليل على تطابق الإصدار.
2. جهّز ملف البيئة خارج Git من `ops/env/staging.env.example`، ووحدات `erp-staging` وأسماء DNS الداخلية وشهادة HTTPS وسلسلة الثقة للجهازين. استخدم شهادات وأسرارًا خاصة ببيئة التجربة. استخدم `-p erp-staging` مع `compose.yaml` و`compose.staging.yaml`. افحص إعداد Compose المدمج محليًا دون حفظ مخرجاته الحاوية للأسرار في محضر العمل.
3. شغّل تهيئة PostgreSQL والترحيلات ومنح دور التشغيل وفق [دليل المستودع](../../README.md)، من ملفات البيئة المعدّة لهذا المثيل. شغّل Nginx على واجهة Staging فقط بعد فحص الإعداد، واجعل اتصاله بالويب عبر loopback. راجع جدار الحماية وأسماء DNS والثقة بالشهادة وعدم نشر منافذ قاعدة البيانات وعامل الطباعة.
4. سجّل نتائج فحص الصحة وHTTPS والأذونات والحفظ والطباعة. في فحص A07، احفظ معاملة ومرفقًا اصطناعيين ثم أعد تشغيل الخدمات بالتتابع بعد انتهاء الطلبات. أثبت مطابقة المرجع وبصمة المرفق وعودة الطباعة. سجّل توقيت كل فحص وربطه ببيان الإصدار. استعد إعداد Nginx والشبكة الموثق إذا فشل تجهيز التجربة.

## اختبار CI والتنظيف

`bash tests/run_s1_12_acceptance.sh` يشغّل حزمة القبول باستخدام أجهزة ومخازن اصطناعية. يشغّل `--lifecycle-check` حالات عزل وتنظيف فعلية بمشروعات مؤقتة. تتضمن بيانات الاختبار حسابات وشهادات مؤقتة. يبقى مسار سجل التشغيل الخاص خارج المستودع. GitHub Actions يسجل زمن الوظيفة، ويطبع السكربت زمن الاختبار والتنظيف ورمزيهما.

يُسجل مسار تشغيل في ملف مؤقت عند الاستدعاء عبر `--run-pointer`. تستخدم خطوة `always()` أمر `--cleanup` مع المؤشر نفسه. إذا توقف المضيف قسرًا، افحص سجل التشغيل ووسوم موارد الاختبار قبل إعادة طلب التنظيف. لا تستخدم أوامر تنظيف عامة أو أوامر حذف أحجام Staging لحذف بقايا CI. يُعد رفض التنظيف عند عدم ثبوت الملكية نتيجة يجب توثيقها.

## الفصل بين الجاهزيات والقبول

- يُعرض التنفيذ الآلي للدمج بعد فحوص CI والمراجعات واعتماد الرأس الصريح. بعد دمجه، يمكن متابعة S1-13 بتفويض مستقل.
- تبقى جلسة المكتب والقبول الميداني معلّقين إلى أن تكون S1-13 جاهزة للاختبار. تُستكمل A05 في محضر الجلسة المشتركة. يستخدم S1-AT-02 مرجع المحضر في تجربة الاستعادة المستقلة.
- إذا ظهر إخفاق في المسودة أو مسار التطبيق، سجّل السلوك الفعلي ومخرجات اختبار إعادة الطلب. أي تعديل في منطق التطبيق أو الواجهة أو مخطط البيانات يحتاج نطاقًا وتفويضًا مستقلين. تظل الجاهزية للاستخدام التجاري خاضعة للبوابات المعتمدة.
