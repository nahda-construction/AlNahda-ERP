# ERP Handover v1.6 — Clean & Lean Baseline

**القرار النافذ:** تطوير ERP مخصص مستقل، دون ERPNext؛ Modular Monolith وتطبيق ويب وPostgreSQL وفق SRS-202/203/206. **الخطوة التالية G2:** اعتماد MVP والحزمة الأولى، وليس مقارنة المنصة أو البرمجة فوراً.

اقرأ `project_state.md` أولاً، ثم `master_srs.md` (v0.7) و`decisions_ledger.md` §3 (النافذ)، §6 (التاريخ)، §8 (سجل التعديل). راجع القاموس والقواعد ونموذج البيانات والصلاحيات بقدر الحزمة قيد التنفيذ. `open_blockers.md` سجل توقيت الإغلاق؛ `acceptance_tests.md` يحوي RTM واختبارات غير منفذة. حافظ على التمييز بين قرار معتمد ومسودة تصميم ومعالجة محاسبية غير معتمدة.

الملفات العشرة في الجذر هي المرجعية النشطة. المجلدات `review/` و`source_original/` أرشيف اختياري؛ ليست شرطاً لاستئناف العمل. لا يعاد تفعيل نص تاريخي إذا خالف قراراً أحدث. لا بدء برمجة قبل الإذن واعتماد الحزمة؛ لا بيانات مالية حية أو نشر خارجي قبل اختبارات واعتمادات البوابة المعنية.
