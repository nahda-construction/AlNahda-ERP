# 1. الغرض من النظام

تطوير نظام ERP مخصص مستقل لشركة النهضة للبناء والتشييد لإدارة أعمال المقاولات والتشطيبات والتصميم والإشراف وإدارة المشروعات.

يهدف النظام إلى توحيد البيانات والإجراءات، وربط التنفيذ بالتكاليف والمشتريات والمقاولين والمالية والبرنامج الزمني والمطالبات والتقارير.

يجب أن يكون النظام ملائماً لشركة صغيرة من حيث سهولة الاستخدام وتكلفة التشغيل، مع توفير بنية قابلة للتوسع مستقبلاً.

**الأهداف:**

- تسجيل البيانات مرة واحدة وإعادة استخدامها في الوحدات المختلفة.
- استخراج التكلفة والربحية لكل مشروع وبند ونطاق أعمال.
- إدارة دورة الشراء والمخزون والمقاولين والمدفوعات.
- دعم نماذج التعاقد المختلفة دون إعادة برمجة النظام لكل مشروع.
- الفصل بين العمليات التشغيلية والاستحقاق المحاسبي والتدفقات النقدية.
- إدارة الصلاحيات والاعتمادات والتصحيحات.
- توفير بوابة إلكترونية للمالك وتقارير للإدارة.
- الحفاظ على سلامة البيانات وإمكانية التتبع والمراجعة.

# 2. المبدأ المعماري الحاكم — ARCH-001

## 2.1 استقلال النظام عن نموذج التعاقد

**متطلب إلزامي معتمد.**

يجب أن يدعم ERP نماذج:

1. Cost Plus — التكلفة الفعلية مضافاً إليها أتعاب.
2. Unit Price / BOQ — المقاولات بسعر الوحدة والمقايسة.
3. Lump Sum — العقود المقطوعية.
4. Mixed Contracts — العقود المختلطة.
5. Design — عقود التصميم الهندسي.
6. Supervision — عقود الإشراف.
7. Project Management — إدارة المشروعات.
8. العقود التي تجمع أكثر من خدمة أو آلية تسعير.

لا يجوز تثبيت نسبة أتعاب أو طريقة مطالبة أو قاعدة ملكية أو طريقة اعتراف بالإيراد داخل البرنامج باعتبارها شرطاً عاماً لجميع المشروعات.

تُحدد القواعد حسب العقد أو نطاق العمل أو الالتزام التعاقدي المعني.

## 2.2 دور مشروع أبو سلطان

يُستخدم مشروع أبو سلطان:

- حالة تطبيق لنموذج Cost Plus.
- مشروعاً تجريبياً لاختبارات التكامل.
- مصدراً لسيناريوهات واقعية للمشتريات والمخزون والمقاولين والتكاليف.
- مثالاً لاختبار بوابة المالك وأتعاب الإدارة.

ولا يُستخدم لتقييد أنواع العقود التي يدعمها النظام.

## 2.3 أسبقية القواعد

عند وجود تعارض بين صياغة عامة قديمة وقرار أحدث معتمد، تُطبق القاعدة الأحدث، مع حفظ سجل القرار السابق باعتباره مستبدلاً.

لا يُعد المثال الرقمي أو سيناريو اختبار لعميل معين سياسة عامة لجميع العملاء.

# 3. نموذج العقود — Contract Model

## 3.1 العقد الرئيسي

لكل مشروع عقد رئيسي مع مالك تعاقدي واحد، وفق SRS-053.

يمكن أن يتضمن العقد الرئيسي:

- نطاقات أعمال متعددة.
- آليات تسعير مختلفة.
- شروط صرف وتحصيل مختلفة.
- بنود أتعاب مستقلة.
- مراحل إنجاز واستحقاق.
- ملاحق وتعديلات وإصدارات معتمدة.

يجوز أن يمتلك المالك عدة مستخدمين مفوضين للدخول إلى بوابة المشروع، دون اعتبارهم ملاكاً تعاقديين إضافيين.

## 3.2 بنود الالتزامات التعاقدية

**[APPROVED] CTR-D01=A وCTR-D02=A:** عقد رئيسي واحد يضم مكونات تعاقدية متعددة. لكل مكون قاعدة تسعير واستحقاق قابلة للضبط بإصدار محدد. بنود التسعير مستقلة عن بنود التنفيذ، مع ربط متعدد إلى متعدد مضبوط ومنع ازدواج القياس والمبالغ، وربط بسيط افتراضي. لا تُفرض بنود تنفيذ وهمية لخدمات التصميم أو الإشراف أو الإدارة.

مثال لعقد مختلط:

| نطاق العمل | طريقة الاستحقاق |
|---|---|
| الأعمال الخرسانية | سعر الوحدة |
| أعمال التشطيبات | مقطوعية |
| إدارة مشتريات المالك | نسبة أتعاب |
| التصميم الداخلي | أتعاب مراحل |

تظهر المطالبات مجمعة أو منفصلة بحسب شروط العقد، دون ازدواج الإيرادات أو المستحقات.

## 3.3 قواعد الاستحقاق بحسب النوع

| النموذج | أساس استحقاق مطالبة المالك |
|---|---|
| Cost Plus | التكاليف المؤهلة وفق العقد + الأتعاب |
| Unit Price | الكميات المستحقة × أسعار الوحدات التعاقدية |
| Lump Sum | مراحل الإنجاز أو القيم والنسب التعاقدية |
| Design | مراحل التصميم أو تسليمات الخدمة |
| Supervision | المدة أو المراحل أو الأتعاب المتفق عليها |
| Project Management | الصيغة التعاقدية المعتمدة |
| Mixed | مجموع نتائج القواعد المطبقة على مكوناته |

يجب فصل الاستحقاق التعاقدي عن الاعتراف المحاسبي بالإيراد، مع تطبيق السياسة المحاسبية المناسبة.

**[APPROVED] CTR-D03=A:** سجل استحقاقات مستقل لكل مكون، يحفظ المصدر وإصدار القاعدة والسابق والحالي والتراكمي والمبلغ المطالب به والمتبقي والتصحيحات. لا تتكرر المطالبة بالحدث ذاته. يحدد العقد شرط الأهلية والمستند والاعتماد، ولا تساوي تكلفة المورد أو نسبة الإنجاز الإيراد أو الاستحقاق تلقائياً.

**[APPROVED] CTR-D04=A — اعتماد معماري:** الفصل بين أداء الالتزام والإيراد وأصل/التزام العقد والذمة والمطالبة والفاتورة والتحصيل؛ الترحيل الآلي محصور في القواعد المحاسبية المعتمدة. التزامات الأداء المحاسبية لا تتطابق بالضرورة مع مكونات التسعير. [REQUIRES ACCOUNTANT APPROVAL] التوقيت والقيود والتصنيف والضرائب.

**[APPROVED] CTR-D05=A:** تعديلات شروط العقد أو آلية تسعيره عبر ملحق وإصدار معتمدين ونطاق نفاذ محدد؛ تظل المطالبات والتكاليف والإصدارات التاريخية محفوظة، والتعديلات الرجعية تسوى بمستند مرتبط، دون مشروع وهمي أو إعادة تسعير صامتة. تصنيف التعديل محاسبياً يحتاج اعتماد المحاسب.

# 5. هيكل المشروعات

**الهيكل المعتمد:**

مشروع ← نطاق أعمال ← بند تنفيذ ← نشاط فرعي 1 اختياري ← نشاط فرعي 2 اختياري.

**[APPROVED] SRS-001 Revision 2:** أُلغي مستوى مجموعة الأعمال؛ لا يوجد نشاط فرعي ثانٍ دون نشاط أول. تُحفظ تبعية البنود عند تعديلها بما يتيح إعادة إنتاج التقارير التاريخية. تفاصيل الإصدارات وقيود الشجرة في النموذج المنطقي [PROPOSED].

ويجب أن يدعم:

- قوالب قياسية قابلة للتخصيص.
- بنود تنفيذ مستقلة لكل نطاق.
- فصل بنود المقايسة عن بنود التنفيذ مع إمكانية الربط بينها.
- أعمالاً بالكميات والأسعار أو المقطوعية.
- ميزانيات أصلية ومعدلة وإصدارات محفوظة.
- توزيع تكاليف الخامات والعمالة والمقاولين والمعدات.
- تحليل الأسعار التفصيلي أو إدخال سعر مباشر.
- التكاليف المشتركة وقواعد توزيعها.
- التقدم الفعلي وقياس الانحرافات.

لا تتغير بنية المشروع الأساسية بسبب اختلاف نوع العقد.

# 6. منظومة التكاليف — COST-001

**قاعدة عامة ملزمة لجميع أنواع العقود.**

يجب أن يدعم النظام استخراج التكلفة حسب:

- المشروع ونطاق الأعمال وبند التنفيذ والنشاط الفرعي الأول والثاني عند وجودهما.
- صنف الخامة.
- نوع التكلفة.
- المورد أو المقاول.
- الفترة الزمنية.
- المستند المصدر.
- مصدر التمويل.
- المسؤولية المالية.

## 6.1 أنواع القيم

يجب الفصل بين:

1. تكلفة الشراء.
2. تكلفة الاستهلاك الفعلي.
3. تكلفة الأعمال المعتمدة.
4. الالتزامات التعاقدية المفتوحة.
5. التكاليف المستحقة وغير المسددة.
6. المبالغ المسددة.
7. التكلفة الاقتصادية الكاملة للمشروع.
8. مصروفات الشركة المعترف بها محاسبياً.
9. القيمة المستحقة على المالك وفق العقد.
10. الإيراد والأرباح المتحققة والمتوقعة.

## 6.2 منع الازدواج

لا يجوز أن يؤدي تسجيل فاتورة، أو صرف خامة، أو دفع مستحق، أو إصدار مطالبة، إلى تكرار نفس التكلفة في تجميع تقارير المشروع.

تُستخدم معرفات المصدر والعلاقات بين المستندات لضمان سلامة التجميع.

**[APPROVED] DM-D02=A، DM-D03=A، DM-D04=A:** التحميل المباشر على البند أو أي نشاط تابع، والتجميع التصاعدي من التخصيصات الأصلية مرة واحدة. التكاليف المشتركة داخل المشروع أو بين مشروعات تحفظ في أوعية مستقلة؛ الرصيد غير الموزع ظاهر ويُراجع عند الإقفال ولا يُفرض توزيعه تقديرياً. المصروفات العامة للشركة منفصلة عن تكلفة التنفيذ. كل تعديل توزيع معتمد يحتفظ بالإصدارات؛ في الفترات المغلقة لا تعديل صامت، بل تسوية موثقة أو معالجة خطأ سابق يحددها المحاسب. إعادة توزيع المصدر لا تنشئ تكلفة أو استحقاقاً جديداً تلقائياً.

**القيد المعتمد SRS-196=B:** لا يوجد فحص إضافي مخصوص لكشف تكرار خامات الشركة داخل تكلفة مستخلص مقاول. يظل هذا استثناءً رقابياً موثقاً، دون إلغاء ضوابط منع تكرار المعاملات والتجميع الحسابي.

# 7. المشتريات والمخازن

## 7.1 الدورة المبسطة — BPM-01 v0.2

1. طلب شراء.
2. اعتماد وتنفيذ الشراء.
3. الاستلام وتسجيل الفاتورة.
4. صرف الخامات وتحميل التكلفة.

تُدار المدفوعات عبر المسار المالي المستقل.

يمكن استخدام Quick Purchase للمشتريات الصغيرة والعاجلة، مع استمرار إنشاء المستندات والاعتمادات المطلوبة في الخلفية.

## 7.2 صلاحيات الشراء

يُسمح بتفويض اعتماد أوامر الشراء حتى 10,000 جنيه مصري وفق DEC-03.

ما يزيد عن الحد يحتاج اعتماد المدير.

يبقى اعتماد فواتير الموردين وجميع عمليات الصرف من اختصاص المدير.

تحتاج سياسة احتساب الحد المالي عند وجود ضرائب وخصومات، ومنع تجزئة الأوامر، إلى تفصيل نهائي.

## 7.3 تقييم المخزون

**السياسة المعتمدة:**

- المتوسط المرجح المتحرك للخامات المتكررة.
- التكلفة المحددة للأصناف المميزة.

تُحسب مجموعة المتوسط للمخزون المخصص باستخدام المشروع + مالك المخزون + الصنف (INV-D01=A). المخزن موقع حيازة مستقل وليس مفتاح التقييم. [APPROVED] DM-D01=A: مخزون النهضة العام غير المخصص مجموعة مستقلة لكل صنف ومالك الشركة، دون مشروع وهمي. تخصيصه لمشروع مملوك للنهضة ينقل القيمة الدفترية ويحدث متوسط الوجهة، ولا يمثل استهلاكاً أو انتقال ملكية أو مصروفاً تلقائياً.

تُحفظ الكميات لكل مخزن بشكل مستقل. تشمل قيمة المخزون تكلفة الشراء والمصروفات المباشرة المؤهلة بعد خصومات الشراء، مع استبعاد الضرائب القابلة للاسترداد والمصروفات العامة غير المؤهلة (INV-D03=A). الأصناف المميزة قابلة للتتبع بتكلفتها الفعلية (INV-D04=A). يبقى FIFO مسموحاً كتسلسل صرف فيزيائي فقط لا سياسة تقييم.

يجب دعم:

- الاستلام الجزئي والفحص والرفض.
- الخامات قيد التوريد.
- النقل بين المخازن.
- الصرف للتنفيذ.
- المرتجعات.
- الجرد والتلف والفاقد.
- التصحيحات السعرية.
- استلام خامات قبل اعتماد الفواتير.
- إعادة تخصيص الخامات بين المشروعات والملاك بموافقة وتسوية معتمدة.

### 7.3.1 التصحيحات المتأخرة وإقفال الفترات

**[APPROVED] INV-D02=A مقيّد بـ DM-D05=B:** إعادة حساب الحركات المتأثرة داخل مجموعة التقييم المعنية في الفترة المفتوحة؛ تسويات موثقة للفترات المغلقة. لا إعادة تقييم تلقائية للمجموعات المستقبلة بعد تحويل المخزون إليها. [PROPOSED] سجل رقابي لفروق السعر غير المنتشرة ومصدرها ومقدارها وحالتها؛ لا إسقاط للفرق ولا تحميل لمخزون غير موجود ولا قيد أصل/مصروف تلقائي. [REQUIRES ACCOUNTANT APPROVAL] تصنيف الفرق وتسويته وأثره على القوائم والربحية؛ متابعة الفروق لا تعني قبول وجود قيمة مخزون غير صحيحة. التفاصيل الزمنية والتقريب [NOT DESIGNED YET].

**[APPROVED] INV-D05=A:** النقل عبر المشروعات أو الملاك استثنائي بموافقات لازمة ومستند وتسوية للحقوق؛ يظل النقل المكاني داخل المجموعة منفصلاً عن التخصيص وانتقال الملكية والصرف.

## 7.4 ملكية المخزون

**قاعدة عامة:** تُحدد الملكية وفق العقد وطبيعة عملية الشراء.

**قاعدة خاصة بأبو سلطان:** الخامات المشتراة والمخصصة للمالك تصبح ملكه منذ الشراء، حتى إذا كانت في المخزن المركزي لشركة النهضة.

لا يجوز تعميم هذه القاعدة على مشروعات المقاولات التي تشتري الشركة خاماتها لحسابها الخاص.

لا تبدأ البرمجة قبل اعتماد النطاق التفصيلي للإصدار المستهدف.
