## 1. بروتوكول القبول

### 1.1 حالات الاختبار

| الحالة | الدلالة |
|---|---|
| [APPROVED] | معيار النتيجة مستند إلى قاعدة وافق عليها المستخدم؛ السيناريو التمثيلي نفسه ينتظر اعتماد الحزمة والتنفيذ |
| [PROPOSED] | سيناريو أو نتيجة تفصيلية مقترحة للمراجعة |
| [BLOCKED] | لا يمكن اعتبار النتيجة المالية/الوظيفية نهائية قبل إغلاق فجوة محددة |
| [MISSING FROM CONTEXT] | نص المتطلب الفردي غير مسترجع؛ لا تُنشأ نتيجة تخمينية باسمه |
| [REQUIRES ACCOUNTANT APPROVAL] | القيد أو التصنيف أو توقيت الإيراد أو الضريبة يحتاج اعتماد المحاسب |
| [NOT DESIGNED YET] | خوارزمية أو شرط أو سياسة الاختبار النهائية لم تُصمم |
| [PLATFORM DEPENDENT] | تفاصيل التنفيذ والبيئة والأداء تتوقف على المكدس والتهيئة المعتمدين |
| [SUPERSEDED] | اختبار أو توقع تاريخي لم يعد معيار قبول سارياً؛ لا ينفذ بوصفه القاعدة الجديدة |

جميع صفوف الاختبار في هذه الوثيقة **NOT RUN — لم تنفذ**، حتى إن كان معيارها [APPROVED]. نتيجة التنفيذ لاحقاً: PASS / FAIL / BLOCKED / NOT RUN، مع دليل فعلي وإصدار التطبيق والبيئة وتاريخ التشغيل. لا يُستخدم PASS لمجرد صحة مثال حسابي على الورق. معرفات UAT الجديدة تنظيمية ولا تمثل قرارات أعمال جديدة.

### 1.2 إعداد البيانات والبيئة

- تُستخدم قاعدة اختبار معزولة، وبيانات نموذجية لا بيانات ملاك حقيقية ولا حسابات مالية إنتاجية. يختبر كل نمط عقد على حدة وفي حالة مختلطة. تنشأ مشروعات ومالكون وموردون ومخازن ومستخدمون مختلفون للتحقق من العزل.
- العملة EGP؛ كل مبلغ معروض بخانتين للجنيه والقرش. الأمثلة المختارة ذات نتائج منتهية عند القرش لا تحسم دقة المتوسط الداخلية أو قواعد تخصيص قرش التقريب (GAP-09). لا ضريبة أو خصم أو احتجاز أو تكاليف إضافية ما لم يُذكر في المثال؛ هذه فرضية اختبار وليست سياسة ضريبية عامة.
- قبل كل اختبار: تثبيت الإصدارات والفترة المفتوحة/المغلقة، الأدوار، الملكية، طريقة التقييم، الحالة الابتدائية وقيمة المصدر، وعزل أثر الاختبارات الأخرى. يُوثق المسار الطبيعي وحالة الرفض وإعادة محاولة العملية والتراجع في حالات الفشل بحسب انطباقها.
- بعد الاختبار: مقارنة رصيد المخزون والحركة المصدرية وتخصيصات التكلفة وسجل الاستحقاق والمطالبة والذمة والقيد والمبالغ المدفوعة كلٌّ في مساره. يجب أن تكون جميع الفروق مفسرة بمستند، لا أن تتساوى كل السجلات لمجرد المقارنة. تُراجع السجلات غير المتأثرة للتأكد من عدم حدوث أثر جانبي.
- عند وجود قيود مالية مقترحة، لا يُختبر التشغيل الإنتاجي على أساسها قبل اعتماد المحاسب. يقتصر PoC على إثبات قابلية تنفيذ القاعدة وتقييم النتيجة التشغيلية أو قيد تجريبي موسوم، ودون ادعاء مطابقة محاسبية نهائية.

### 1.3 أدلة التنفيذ ومعايير الإغلاق

لكل اختبار تُحفظ المدخلات الفعلية، المعرفات والإصدارات، خطوات التنفيذ، القيم قبل وبعد، حركات المصدر وقيود اليومية عند انطباقها، سجل الاعتماد/الرفض، دليل صلاحية الوصول (للأمان)، النتيجة والملاحظات. يُسجل الخطأ ومصدره وخطورته ويعاد اختبار التصحيح والمسارات المرتبطة. لا يُسمح بتغيير النتيجة المتوقعة لمجرد أن التطبيق أعطى نتيجة مختلفة؛ أي تعديل في قاعدة الاختبار يحتاج مصدر قرار.

البوابات G0–G5 في project_state.md؛ اختبار كل حزمة قبل قبولها، والقيود المحاسبية الحية والأمن والترحيل والاستعادة قبل التشغيل المتعلق بها.
