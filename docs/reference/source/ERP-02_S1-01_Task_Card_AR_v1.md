# ERP-02 | بطاقة S1-01 — تأسيس المستودع والبيئة

**الأولوية P0 · للاعتماد في G3 · إذن التنفيذ ينتظر موافقة مستقلة**

**الهدف** تأسيس مستودع Git محلي واحد وبيئتي تطوير واختبار مستقلتين بحاويات Linux، وتشغيل نواة Django بلا وحدات أعمال، مع PostgreSQL واتصال موثق وفحوص تسليم قابلة للتكرار. يشغّل Gunicorn خدمة `web` عبر WSGI داخل حاوية Linux باستخدام `config.wsgi:application`.

### جذر المستودع ونقطة البداية

| البند | التعيين المقترح |
|---|---|
| الجذر | `/home/engah/code/AlNahda-ERP` هو جذر مستودع المشروع المقترح للتنفيذ، وهو مسار محلي خارج OneDrive. يعتمد التطوير والاختبار في S1-01 على الـHDD الحالي، وتُعاد دراسة الحاجة إلى SSD قبل اعتماد جهاز التشغيل الفعلي. |
| نقطة البداية | مستودع جديد فارغ، وبالتالي لا يوجد commit سابق يمكن الإحالة إليه. بعد إذن التنفيذ، أعد التحقق من المسار المسجّل في فحص الجاهزية. سجّل جذر Git وحالته، وأنشئ main وبداية مرجعية محلية معتمدة في البطاقة ثم فرع `s1/01-compose`. إذا ظهر مستودع أو ملفات قائمة، أثبت حالتها واعرض تعارض نقطة البداية قبل أي تغيير. |
| بيئة التنفيذ | يعمل Codex داخل Ubuntu على WSL2 بصلاحيات Workspace ‏(Ask for approval). في S1-01 ينفّذ صاحب المشروع أوامر Docker من نافذة Ubuntu العادية في مجلد المشروع باستخدام سياق `rootless`، ثم يعيد نتائجها إلى جلسة التطوير. تُعتمد نتائج التشغيل المحلي في Ubuntu لإثبات اختبارات القبول التي تتطلب Docker. |
| البيئات | `erp-dev` و`erp-test` بأسماء Compose وملفات إعداد وأسرار وشبكات وقواعد ووحدات تخزين منفصلة. يُربط مدخل كل بيئة بـloopback ومنفذ محلي مختلف مبدئيًا. قاعدة PostgreSQL على شبكة Compose الداخلية. |
| التوليفة | Django 5.2 LTS وGunicorn ومشغل psycopg 3 وصورة PostgreSQL 18 قيد الإثبات. سجل الإصدارات الفعلية وبصمات الصور المستخدمة. يتم قبول الإصدارات الدقيقة وتوافقها خلال S1-02 واستكمال أدلته من بطاقات النواة. |

**أدلة الجاهزية المسجّلة.** وفق نتائج الفحص التي قدّمها صاحب المشروع، أعاد Docker Rootless على Ubuntu نوع المحرك `linux` وظهر `name=rootless`، وإصدار Docker Compose الظاهر هو `v5.8.0`. نجح اختبار إنشاء ملف مؤقت في `/home/engah/code/AlNahda-ERP` والكتابة فيه وقراءته وحذفه، بنتيجة `WRITE_OK`. يظل تشغيل بيئتي التطوير والاختبار والتحقق منهما ضمن قبول تنفيذ S1-01.

| `compose.yaml`، `Dockerfile`، `requirements.in`، `requirements.txt` | الخدمات الأساسية web وdb والبناء واعتماديات Django وpsycopg وGunicorn لتشغيل خدمة `web` عبر `config.wsgi:application`. `requirements.txt` يسجل حزم تجربة البطاقة على أن تُقبل التوليفة في مسار S1-02. |
| `manage.py`، `config/__init__.py`، `config/settings.py`، `config/urls.py`، `config/wsgi.py` | أقل إعداد Django قابل للتشغيل، مع نقطة `/healthz/` تفحص اتصال قاعدة البيانات وترد بحالة مجردة. |
| `ops/env/dev.env.example`، `ops/env/test.env.example` | أمثلة إعداد دون أسرار داخل المستودع. تُحفظ ملفات الإعداد الفعلية التي تحتوي أسرارًا خارج المستودع وأي مسار متزامن، ويشير Compose إلى مساراتها المحلية عند التشغيل. |
| `docs/reference/README.md` | فهرس روابط مرجع v1.6 و2A و2B وهذه المواصفة والبطاقة. |
| `tests/__init__.py`، `tests/test_health.py` | تحقق أساسي من صحة التطبيق واتصال PostgreSQL ضمن بيئة الاختبار. |

تنحصر البطاقة في تهيئة Git وCompose وDjango الأساسي وفحوصه. تُنفذ نماذج المشروعات والمخزون وقيودها والطباعة وDjango Ninja والنسخ والاستعادة في بطاقاتها المحددة. يمتنع العمل على بيانات إنتاج أو تشغيل بوابة المالك أو نشر المستودع خارجيًا في هذه البطاقة.

### القبول والأدلة

يُنفّذ صاحب المشروع فحوص القبول التي تتطلب Docker من نافذة Ubuntu العادية في مجلد المشروع باستخدام سياق `rootless`، ويعيد نتائجها إلى جلسة تطوير Codex للمراجعة والتوثيق.

1. أرفق أدلة الجاهزية المسجّلة قبل التنفيذ، وبصمة الصور والـcommit المرجعي. اعرض جذر Git وحالة الملفات النظيفة باستثناء تغييرات البطاقة المعروفة.
2. شغّل البيئتين باسمَي مشروع مختلفين. سجّل نتيجة `docker compose config --quiet` و`ps` وسجل الصحة دون إخراج أسرار. يُثبت اختلاف الشبكات ووحدات قاعدة البيانات وإعدادات الاتصال. سجّل تحققًا اصطناعيًا بسيطًا يثبت أن سجلاً في إحداهما لا يظهر في الأخرى.
3. طبّق ترحيلات Django الأساسية فعليًا في القاعدتين. سجّل `showmigrations` ونتيجة `/healthz/` من كل بيئة، واسم إصدار PostgreSQL والتحقق أن منفذ القاعدة غير منشور على المضيف. أثبت من إعداد `web` وسجل تشغيلها أن Gunicorn يستخدم `config.wsgi:application` داخل حاوية Linux.
4. في الاختبار، شغّل `python manage.py check` و`python manage.py makemigrations --check --dry-run` واختبار الصحة. أعد تشغيل بيئة وأثبت استقلال الأخرى واستمرار بيانات الأولى عبر إعادة التشغيل.
5. سلّم الفرق وأسماء الملفات ونتائج الفحوص وخطة الرجوع. يراجع صاحب المشروع أو من يفوضه الفرق قبل الدمج.

### الرجوع

يوقف صاحب المشروع مشروع Compose الخاص بالمهمة وحده من نافذة Ubuntu العادية بسياق `rootless`، مع حفظ وحداته وبيانات الاختبار. قبل الدمج تبقى تغييرات الفرع معزولة عن main. بعد الدمج استخدم git revert على فرع مراجعة. استخدم نسخة سابقة من الصورة والإعدادات عند ثبوت التوافق. أرشف أي دليل قبول مطلوب قبل تنظيف الموارد الاصطناعية، وتُراجع خطوة حذف البيانات على حدة بعد تحديد وحدات المشروع المستهدفة.

**اعتماد البطاقة** الجذر ونقطة البداية، المضيف الذي سيشغّل Linux، قائمة المسارات ومعايير القبول. بعد مراجعة المواصفة والبطاقة يصدر إذن مستقل قبل إنشاء مستودع Git أو بدء S1-01، ويخص هذه البطاقة وحدها.
